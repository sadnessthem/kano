## 1. 项目概述

### 1.1 一句话描述

一个基于 PyQt5 + Live2D Web 渲染的桌面角色程序，角色常驻桌面，支持拖拽、点击交互、智能空闲行为、系统事件反馈，后期可扩展为 AI 对话助手。

### 1.2 项目愿景

让二次元角色「活」在你的桌面上。她不只是动，还会感知你的状态、主动与你互动、在你工作时默默陪伴。从「花瓶」到「伙伴」。

### 1.3 目标用户画像

- 原神/星铁/绝区零玩家，想要一个桌面临演角色
- 码农 / 设计师 / 学生，长时间面对电脑想要一点陪伴感
- 虚拟主播 / 二创作者，需要一个可定制的角色展示工具

### 1.4 设计哲学

| 原则 | 说明 |
|------|------|
| **离线优先** | 所有核心功能不依赖网络，数据全在本地 |
| **低侵入** | 不干扰用户正常操作，鼠标穿透模式可选 |
| **可定制** | 模型、台词、行为均可通过配置文件修改 |
| **渐进增强** | MVP 跑通骨架 → 逐步叠加智能行为 |

### 5.1 窗口管理器 (window_manager.py)

```python
class WindowManager(QMainWindow):
    """
    职责：
    - 创建和管理透明无边框置顶窗口
    - 处理鼠标拖拽移动
    - 控制鼠标穿透模式
    - 管理窗口位置持久化
    """

    # --- 属性 ---
    is_topmost: bool          # 是否置顶
    is_draggable: bool        # 是否可拖拽
    is_click_through: bool    # 是否鼠标穿透
    scale: float              # 模型缩放倍率
    position: tuple[int,int]  # 屏幕坐标 (x, y)
    drag_offset: tuple[int,int]  # 拖拽偏移量
    screen_geometry: QRect    # 当前屏幕尺寸

    # --- 公开方法 ---
    def __init__(self, config: dict):
        """初始化窗口：设置 flags、加载 webview、连接信号"""

    def setup_window(self):
        """配置 Qt 窗口属性：透明背景、无边框、工具窗口类型"""

    def toggle_topmost(self) -> bool:
        """切换置顶状态，返回新状态"""

    def toggle_click_through(self) -> bool:
        """切换鼠标穿透（Windows: WS_EX_TRANSPARENT + WS_EX_LAYERED）"""

    def set_scale(self, scale: float):
        """缩放模型 (0.5~2.0)，同步前端缩放"""

    def move_to(self, x: int, y: int):
        """移动到指定屏幕坐标（含边界约束）"""

    def save_position(self):
        """保存当前位置到 config.yaml"""

    def load_position(self) -> tuple[int, int]:
        """从 config.yaml 加载上次位置"""

    def get_valid_position(self, x: int, y: int) -> tuple[int, int]:

    def _on_mouse_press(self, event: QMouseEvent):

    def _on_mouse_release(self, event: QMouseEvent):

class ClickThroughFilter(QObject):
    """Windows 鼠标穿透事件过滤器，通过 nativeEvent 设置 WS_EX_TRANSPARENT"""
```

**实现细节：**

- 透明背景：`setAttribute(Qt.WA_TranslucentBackground)`
- 无边框：`Qt.FramelessWindowHint`
- 置顶：`Qt.WindowStaysOnTopHint`
- 鼠标穿透（Windows）：`pywin32` 的 `SetWindowLong` 设置 `WS_EX_TRANSPARENT | WS_EX_LAYERED`
- 拖拽：重写 `mousePressEvent` / `mouseMoveEvent` / `mouseReleaseEvent`
- DPI 适配：`QApplication.setAttribute(Qt.AA_EnableHighDpiScaling)`

### 5.2 通信桥 (bridge.py)

```python
class Bridge(QObject):
    """
    Python ↔ JS 双向通信桥

    Python 侧（QWebChannel 注册对象）：
    - JS 通过 channel.objects.bridge.callMethod() 调用
    - Python 通过 self.page().runJavaScript() 发送命令

    设计原则：
    - 所有通信使用 JSON 格式
    - JS 调用 Python 的方法统一路由到 handle_js_event()
    - Python 发往 JS 的方法统一使用 send_command()
    """

    # Python 侧供 JS 调用的槽（通过 QWebChannel 暴露）
    # 所有 JS → Python 事件经由此方法路由
    @pyqtSlot(str)
    def handle_js_event(self, json_str: str):
        """
        接收 JS 上报的事件 JSON 字符串
        解析后分发到 behavior_engine.handle_event()
        """

    # Python → JS 发送命令
    def send_command(self, action: str, params: dict = None):
        """
        向 JS 发送命令
        action 可选值：
          - playMotion:     播放动作组  params: {group, index, priority}
          - setExpression:  切换表情    params: {expression_id}
          - showDialog:     显示对话    params: {text, duration}
          - setScale:       设置缩放    params: {scale}
          - setDraggable:   切换拖拽    params: {enabled}
          - setVisibility:  设置可见性  params: {visible}
        """

    # JS 前端就绪的回调
    @pyqtSlot()
```

### 5.3 行为引擎 (behavior_engine.py)

```python
class BehaviorEngine(QObject):
    """
    行为引擎：角色行为的决策核心

    职责：
    - 运行 FSM 状态机
    - 根据事件源决定执行哪个行为
    - 管理行为优先级和冷却

    策略：
    - 行为按优先级排队，高优先级打断低优先级
    - 同一行为有冷却时间，冷却期间不会触发
    - 随机行为有加权随机选择
    """

    # --- 状态枚举 ---
    class State(Enum):
        IDLE = 0           # 待机（默认）
        ACTING = 1         # 执行动作中
        SLEEPING = 2       # 空闲睡眠
        GREETING = 3       # 问候/欢迎
        INTERACTING = 4    # 用户交互中

    # --- 公开方法 ---
    def __init__(self, bridge: Bridge):
        """初始化状态机，注册事件处理器"""

    def start(self):
        """启动行为引擎（启动定时器、随机行为调度）"""

    def stop(self):
        """停止所有定时器"""

    def handle_event(self, event_type: str, data: dict = None):
        """
        事件入口（被 bridge 调用）
        event_type: click | doubleClick | dragEnd
                    | idle_timeout | return_from_idle
                    | system_event | scheduled_event
                    | motion_finished
        """

    def set_state(self, new_state: State):
        """状态切换 + 进入/退出回调"""

    # --- 内部方法 ---
    def _process_event(self, event: dict):
        """事件处理管线：优先级判断 → 冷却检查 → 执行行为"""

    def _select_action(self, scene: str) -> dict:
        """根据场景选择行为（动作 + 台词 + 表情），支持加权随机"""

    def _is_on_cooldown(self, action_id: str) -> bool:
        """检查行为是否在冷却中"""

    def _set_cooldown(self, action_id: str, cooldown_seconds: int):
        """为行为设置冷却"""

    def _schedule_random_action(self):
        """调度 30~90 秒后的随机行为"""

    def _on_idle_timeout(self, minutes: int):
        """空闲超时回调：根据分钟数选择对应的空闲等级动作"""

    def _on_return_from_idle(self):
        """用户回归回调：打断空闲状态，触发欢迎动作"""
```

**状态转换表：**

```
当前状态      事件                   新状态        执行动作
───────────  ───────────────────    ──────────    ────────────────
IDLE         点击                    INTERACTING  单击随机动作
IDLE         空闲 > 1min             IDLE         小动作（发呆）
IDLE         空闲 > 5min             SLEEPING     打哈欠 → 打瞌睡
IDLE         定时器触发               ACTING       随机自主行为
IDLE         整点                     ACTING       报时
IDLE         系统事件                 ACTING       系统提醒
───────────  ───────────────────    ──────────    ────────────────
ACTING       动作结束                 IDLE         回到待机
ACTING       高优先级事件打断         优先事件源    打断当前动作
───────────  ───────────────────    ──────────    ────────────────
SLEEPING     用户操作                 GREETING     惊喜 → 欢迎回来
SLEEPING     (保持安静)              SLEEPING     继续睡
───────────  ───────────────────    ──────────    ────────────────
GREETING     问候动作结束             IDLE         回到待机
───────────  ───────────────────    ──────────    ────────────────
INTERACTING  交互动作结束             IDLE         回到待机
```

## 6. 行为状态机详细设计

### 6.1 空闲行为分级

```
空闲时间轴
──────────────────────────────────────────────────────────────→

 0min ─── 正常待机 ───  循环播放 idle 动作
  │                      偶尔随机动作（摸头发/看四周）
  │
 1min ─── 一级空闲 ───  动作频率降低
  │                      播放一次「发呆」动作
  │                      台词（概率 30%）：「好安静啊…」
  │
 3min ─── 二级空闲 ───  播放「打哈欠」动作
  │                      台词（概率 50%）：「哈啊~有点困了…」
  │
 5min ─── 三级空闲 ───  播放「坐下/蹲下」动作
  │                      台词（概率 70%）：「唔…好无聊…」
  │
10min ─── 四级空闲 ───  播放「打瞌睡」循环动画
  │                      台词（在睡着前说）：「那我先睡一……Zzz」
  │                      不再触发新台词，只播放呼吸动画
  │
15min+ ── 五级空闲 ───  进入「睡眠」状态，循环播放睡觉动画
                         气泡显示 Zzz 符号
                         此时只有「用户操作」可以打断
```

### 6.2 回归行为链

```
用户操作触发回归 ─────────────────────────────────────────→ 完整行为链：

Step 1: [惊醒动画]
         身体微震 → 抬头 → 揉眼睛    时长: ~0.8s

Step 2: [识别用户]
         定睛看 → 表情从迷茫变开心    时长: ~0.5s

Step 3: [开心动作]
         根据空闲等级选择：
           - 浅度(1-3min): 微笑 + 挥手
           - 中度(3-10min): 站起来 + 伸懒腰 + 挥手
           - 深度(10min+): 跳起来 + 大幅度挥手

Step 4: [台词]
         根据空闲等级选择对应台词：
           - 浅度: "你回来啦~"
           - 中度: "欢迎回来！我等你好久了！"
           - 深度: "啊！你终于回来了！我都睡着了…"

Step 5: [回归待机]
         回到 IDLE 状态，重置空闲计时器
```

### 6.3 行为优先级矩阵

```
优先级  行为类别              场景                    打断当前行为？  冷却时间
─────────────────────────────────────────────────────────────────────────────
1(最高) 用户直接交互          点击、双击、拖拽        是              15s
2       系统紧急反馈          CPU过高、电池低         是              5min
3       用户回归              空闲→活跃              是              30s
4       定时问候              整点报时、时段切换      否（排队）      1h
5       随机自主行为          空闲随机动作            否（排队）      30~90s
6(最低) 空闲降级              空闲等级上升            是（平滑过渡）  N/A
```

### 7.2 台词选择算法

```python
def select_dialog(scene: str) -> dict:
    """
    对话选择算法

    1. 根据 scene 找到对应的 dialog_set
    2. 排除历史队列（最近5条）中的台词
    3. 按 weight 加权随机选择
    4. 将选中台词加入历史队列
    5. 如果历史队列占满且所有台词都用过 → 清空队列重新选择
    6. 返回 {text, emotion, action, duration}

    加权随机实现：
    - 计算所有可用台词的总权重 total_weight
    - random(0, total_weight) 决定选中哪个
    - weight 越高被选中的概率越大
    """
```

## 9. UI/UX 设计

### 9.1 视觉设计原则

1. **极简**：窗口中只有角色本体和对话气泡，无其他 UI 元素

## 12. 风险与对策

| 风险 | 影响 | 概率 | 对策 |
|------|------|------|------|
| Live2D 模型版权问题 | 高 | 中 | 开发期使用官方免费模型 Hiyori，用户自行导入自有模型 |
| QWebEngineView 渲染性能 | 中 | 中 | 前端启用硬件加速，空闲降帧至 20fps，交互才恢复 60fps |
| pynput 全局 Hook 被杀软拦截 | 中 | 低 | 添加 GetLastInputInfo fallback 模式；引导用户添加白名单 |
| Live2D Cubism SDK 许可限制 | 高 | 低 | 确认使用 Cubism WebGL SDK Free 版本，遵循二次发布条款 |
| Windows DPI 缩放导致模糊 | 中 | 中 | Qt 启用 AA_EnableHighDpiScaling；前端考虑 devicePixelRatio |
| PixiJS WebGL 在某些显卡不兼容 | 中 | 低 | Canvas 模式降级；启动时检测 WebGL 支持 |
| QWebEngineView 加载本地文件 CORS | 中 | 高 | 使用 qrc 资源系统或本地 HTTP 服务器服务前端文件 |
| 长时间运行内存泄漏 | 中 | 中 | tracemalloc 追踪；定时清理 Live2D 纹理缓存 |
